15  ·  Attention Over Time

Building One

The module in sixty lines, and one forward pass from three raw streams to a scalar loss.

Everything up to here has been equations and shapes. This page writes the module down as code, wires three very different streams into it, puts an ordinary multi-head attention on top, and takes the whole thing to a cross-entropy loss. Every shape quoted below was printed by running the code, not worked out on paper.

The point is not an efficient implementation. It is that the architecture of section 14 is small enough to hold in your head, and that nothing surprising happens when you actually run it.

The module

Two classes. The first is the time embedding of section 09, one linear coordinate and $d_r - 1$ periodic ones. The second is everything from (E2) to (E7). The comments name the equation each line implements. 

class Time2Vec(nn.Module):                                   # (E1)
    def __init__(self, d_r):
        super().__init__()
        self.linear   = nn.Linear(1, 1)
        self.periodic = nn.Linear(1, d_r - 1)
    def forward(self, t):                    # t: (B, L) -> (B, L, d_r)
        t = t.unsqueeze(-1)
        return torch.cat([self.linear(t), torch.sin(self.periodic(t))], dim=-1)

class MTAND(nn.Module):                                      # (E2)-(E7)
    def __init__(self, D_in, J, d_r=64, H=4):
        super().__init__()
        assert d_r % H == 0
        self.H, self.d_k = H, d_r // H
        self.Wq = nn.Linear(d_r, d_r, bias=False)
        self.Wk = nn.Linear(d_r, d_r, bias=False)
        self.U  = nn.Linear(D_in * H, J)
    def forward(self, phi_q, phi_k, values, mask):
        # phi_q (B,K,d_r)  phi_k (B,L,d_r)  values (B,L,D)  mask (B,L,D)
        B, K, _ = phi_q.shape
        D = values.size(-1)
        q = self.Wq(phi_q).view(B, K, self.H, self.d_k).transpose(1, 2)   # (B,H,K,d_k)
        k = self.Wk(phi_k).view(B, -1, self.H, self.d_k).transpose(1, 2)  # (B,H,L,d_k)
        e = q @ k.transpose(-2, -1) / self.d_k ** 0.5                     # (B,H,K,L)   (E3)
        e = e.unsqueeze(-1).expand(-1, -1, -1, -1, D)                     # (B,H,K,L,D)
        e = e.masked_fill(mask[:, None, None] == 0, float("-inf"))
        a = torch.softmax(e, dim=3).nan_to_num(0.0)                       # over L      (E4)
        xh = (a * values[:, None, None]).sum(dim=3)                       # (B,H,K,D)   (E5)
        xh = xh.transpose(1, 2).reshape(B, K, self.H * D)                 # fold (h,d)
        return self.U(xh)                                                 # (B,K,J)     (E6,E7)

Three lines in that block are the ones worth staring at.

  • e.unsqueeze(-1).expand(..., D) is where one score per $(h, k, \ell)$ becomes one score per $(h, k, \ell, d)$. The scores themselves do not depend on the channel, but the mask does, so the same score is about to be normalised $D$ different ways.
  • softmax(e, dim=3) normalises over the key axis and nothing else. That single argument is the whole of (E4), and getting it wrong is the classic way to break this module: normalising over queries would make reference points compete with each other, which is meaningless.
  • .nan_to_num(0.0) handles a channel with no observations at all. Every logit in that row is $-\infty$, the softmax is $0/0$, and the sensible answer is a row of zeros. This is the zero block that section 14 relies on, made explicit in one call.

Note also what is not there. No $W_v$, no projection of the values, no positional encoding, no causal mask, and no reference to what any channel means.

Three streams

The running example from section 14, made concrete. One scalar stream and two pre-embedded ones.

stream $f_b$ $L_b$ $D_b$ mask $J_b$
labs and vitals identity 300 12, fed as 24 $L_1 \times 12$, holey 64
notes a frozen text encoder 7 768 $L_2$, striped 64
prior diagnoses an embedding table 15 128 $L_3$, striped 32

The scalar stream is fed as $[\,V_1 \;\|\; M_1\,]$, which is why its 12 channels enter the module as 24. The two embedded streams take their masks per event and broadcast them across the full width, which is the single line m[..., None].expand_as(v) below. The three output widths deliberately disagree. 

class Encoder(nn.Module):
    def __init__(self, D_ts=12, d_note=768, n_codes=2000, d_code=128,
                 K=48, d_r=64, H=4, J1=64, J2=64, J3=32):
        super().__init__()
        self.K = K
        self.phi   = Time2Vec(d_r)                 # one clock, shared
        self.codes = nn.Embedding(n_codes, d_code, padding_idx=0)
        self.m1 = MTAND(2 * D_ts, J1, d_r, H)      # values are [x || m]
        self.m2 = MTAND(d_note,   J2, d_r, H)
        self.m3 = MTAND(d_code,   J3, d_r, H)
    def forward(self, ts_v, ts_t, ts_m, nt_e, nt_t, nt_m, dx_i, dx_t, dx_m):
        B = ts_v.size(0)
        r   = torch.linspace(0, 1, self.K).expand(B, -1)
        pq  = self.phi(r)
        A1 = self.m1(pq, self.phi(ts_t), torch.cat([ts_v, ts_m], -1),
                                          torch.cat([ts_m, ts_m], -1))
        A2 = self.m2(pq, self.phi(nt_t), nt_e, nt_m[..., None].expand_as(nt_e))
        cv = self.codes(dx_i)
        A3 = self.m3(pq, self.phi(dx_t), cv, dx_m[..., None].expand_as(cv))
        return torch.cat([A1, A2, A3], dim=-1), (A1, A2, A3)

One Time2Vec is constructed and handed to all three modules, so every stream is read on the same learned clock. One line, and it is the difference between the models that share a clock and the models that do not.

Attention over the grid, and the loss

Now the payoff. The concatenated array is regular, so from here on we are allowed to use ordinary attention, and we do: a stock transformer encoder layer over the $K$ reference points. 

class Model(nn.Module):
    def __init__(self, J=160, n_heads=8, n_classes=2):
        super().__init__()
        self.enc  = Encoder()
        self.attn = nn.TransformerEncoderLayer(J, n_heads, 4 * J, batch_first=True)
        self.head = nn.Linear(J, n_classes)
    def forward(self, *b):
        A, parts = self.enc(*b)
        Z = self.attn(A)
        return self.head(Z.mean(dim=1)), A, parts

Two attentions, and they are not the same attention

This page contains two attention mechanisms and it is worth naming the difference, because it is the whole argument of the tutorial in one place.

Inside mTAND, the score is a function of two times and nothing else. The measurement is a value and never reaches the score, so the module can say when and never what. That is what let it eat an irregular record.

In self.attn, the score is the ordinary content-based one: a projection of a row against a projection of another row, exactly the mechanism this tutorial started with in section 01. It is usable here, and only here, because its input is finally a regular sequence of $K$ rows.

The first attention exists so that the second one can be ordinary.

What actually comes out

Running the whole thing on a batch of 4 records of random data, with $K = 48$, $d_r = 64$ and $H = 4$:

after object shape
in labs and vitals, values and mask (4, 300, 12) twice
in note embeddings (4, 7, 768)
in diagnosis code ids (4, 15)
(E7) $A_1$, $A_2$, $A_3$ (4, 48, 64), (4, 48, 64), (4, 48, 32)
(E17) $A$, concatenated (4, 48, 160)
attention $Z$ (4, 48, 160)
mean over $K$ one vector per record (4, 160)
head logits, then cross entropy (4, 2), then a scalar

809,602 parameters, and gradients reach the Time2Vec frequencies, so the clock really is learned rather than fixed. The loss on the first pass was 0.6065 against $\log 2 \approx 0.693$ for a coin flip, which on random data with random labels means nothing at all except that the graph is connected. There is no trained model on this page and no result to report.

Four things worth asserting

If you build this, these are the checks that catch the mistakes that actually happen. All four were run against the code above and the printed output is quoted.

  1. Weights over an observed channel sum to one. Printed 1.0000, 1.0000, 1.0000. If this is not one, the softmax is on the wrong axis.
  2. Weights over a channel with no observations sum to zero. Printed 0.0, 0.0, 0.0, and the resulting $\hat{x}$ is exactly zero. Not uniform, not nan. This is the behaviour section 14 leans on when a whole stream is absent.
  3. The output shape does not depend on how much arrived. Feed the same module 5, 300 and 4000 observations and it returns (1, 48, 64) every time. That invariance is the entire product of the module, so it deserves an assertion rather than a hope.
  4. Gradients reach the embedding frequencies. If they do not, you have accidentally built the fixed positional encoding of section 06 with extra steps.

What this leaves out

  • It is not causal. Every reference point attends to every observation, including later ones. For a real-time task you have to mask keys later than the query, and the same goes for the attention over the grid.
  • The expansion to (B, H, K, L, D) is the memory cost. With $L$ in the thousands this single intermediate dominates everything else. The query axis can be processed in slices, because the softmax normalises over keys and reference points never interact, so nothing is approximated by doing so.
  • Mean pooling over the grid throws the time axis away at the very last step, after all the work of building it. A task that cares about when something happened should read $Z$ rather than its mean.
  • No training loop, no data, no plots. This page verifies that the shapes compose and that the module behaves at its edge cases. It says nothing about whether any of it works.
